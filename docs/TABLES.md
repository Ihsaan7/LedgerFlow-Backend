# LedgerFlow Database Schema

## Tables

### `organizations`
Companies using LedgerFlow; each row represents a tenant.

* `id`: UUID primary key.
* `name`: required company name.
* `slug`: required, globally unique identifier.
* `currency`: required; `PKR` or `USD`.
* `created_at`, `updated_at`: timestamps.

### `users`
People who belong to an organization.

* `id`: UUID primary key.
* `organization_id`: required foreign key to `organizations`.
* `email`, `password_hash`: required.
* `role`: `owner`, `admin`, `sales`, or `viewer`.
* `is_active`: defaults to `true`.
* `created_at`, `updated_at`: timestamps.
* `(organization_id, email)` is unique.
* `(organization_id, id)` is unique to support tenant-scoped references.

### `accounts`
An organization's accounting buckets, such as Cash and Accounts Receivable.

* `id`: UUID primary key.
* `organization_id`: required foreign key to `organizations`.
* `code`, `name`: required.
* `account_type`: `asset`, `liability`, `equity`, `revenue`, or `expense`.
* `is_active`: defaults to `true`.
* `created_at`, `updated_at`: timestamps.
* `(organization_id, code)` and `(organization_id, id)` are unique.

### `products`
An organization's product catalog and current stock.

* `id`: UUID primary key.
* `organization_id`: required foreign key to `organizations`.
* `sku`, `name`: required.
* `quantity_on_hand`: whole number; defaults to `0` and cannot be negative.
* `is_active`: defaults to `true`.
* `created_at`, `updated_at`: timestamps.
* `(organization_id, sku)` and `(organization_id, id)` are unique.

### `customers`
Buyers associated with an organization.

* `id`: UUID primary key.
* `organization_id`: required foreign key to `organizations`.
* `name`: required; `email` is optional.
* `is_active`: defaults to `true`.
* `created_at`, `updated_at`: timestamps.
* `(organization_id, id)` is unique for tenant-scoped references.
* There is no directly updated customer balance column.

### `journal_entries`
Headers for financial events, such as a credit sale or payment.

* `id`: UUID primary key.
* `organization_id`: required foreign key to `organizations`.
* `customer_id`: optional; when present, the composite foreign key requires the customer to belong to the same organization.
* `description`: required.
* `created_at`: creation timestamp.
* `(organization_id, id)` is unique for tenant-scoped ledger-line references.

### `ledger_lines`
Financial effects grouped under a journal entry.

* `id`: UUID primary key.
* `organization_id`: required foreign key to `organizations`.
* `journal_entry_id`, `account_id`: required.
* Composite foreign keys require the entry and account to belong to the same organization as the line.
* `direction`: `debit` or `credit`.
* `amount_minor`: positive `BIGINT` in paisa for `PKR` or cents for `USD`.
* `created_at`: creation timestamp.

### `idempotency_records`
Records intended to help the backend recognize request retries.

* `id`: UUID primary key.
* `organization_id`: required foreign key to `organizations`.
* `idempotency_key`, `request_hash`: required.
* `status`: `processing` or `completed`.
* `response_status`, `response_body` (`JSONB`), `completed_at`: `null` while processing and required when completed.
* `created_at`: creation timestamp.
* `(organization_id, idempotency_key)` is unique.

### `audit_events`
Records intended to describe important actions.

* `id`: UUID primary key.
* `organization_id`: required foreign key to `organizations`.
* `actor_user_id`: optional; when present, a composite foreign key requires the user to belong to the same organization.
* `action`, `entity_type`, `entity_id`, `changes`: required.
* `changes` is `JSONB`; `entity_id` is not a foreign key.
* `created_at`: creation timestamp.

---

## Shared Conventions

* UUID primary keys are generated by default.
* Timestamps use PostgreSQL `TIMESTAMPTZ`.
* `updated_at` does not update automatically; application code must set it.
* The defined foreign keys use `ON DELETE RESTRICT`.
* Each organization uses `PKR` or `USD`; currency conversion is outside v1.

---

## Known Gaps

The schema is an initial foundation, not a complete production ledger:

* Balanced journal entries and ledger immutability are not yet enforced.
* Audit events are not yet protected against updates or deletes.
* Currency changes after financial activity are not yet prevented.
* Tenant-scoped foreign keys do not replace API authorization and tenant filtering.
* Stock checks do not replace concurrency control and row locking.
* Idempotent retry behavior and atomic transaction flows are not yet implemented.
* Sales, payment allocation, and inventory movement history still need design.
